# AI Safety & Fraud Risk Analytics Platform

An end-to-end analytics and machine-learning platform with two connected risk systems:

1. **Financial Fraud Detection**: scores mobile-money transactions for fraud risk and explains each score.
2. **LLM Safety / Prompt Risk Detection**: classifies user prompts as safe or potentially manipulative (prompt injection, jailbreak, prompt extraction).

> **Status:** Phase 1, project setup and fraud data exploration.
> No models have been trained yet. This README only reports metrics and findings after they have been computed from real data.

---

## Business Problem

**Fraud.** Payment providers have to stop fraudulent transfers without blocking legitimate customers. Fraud is rare, so a model that predicts "not fraud" for everything looks highly accurate and is useless. The platform needs to rank transactions by risk, explain why each one was flagged, and let analysts choose the trade-off between missed fraud (false negatives) and wasted investigations (false positives).

**LLM safety.** Applications built on LLMs receive prompts that try to override instructions, extract system prompts or bypass safeguards. The platform tests whether lightweight, traditional NLP models can screen these prompts cheaply before they reach an expensive LLM.

## Dataset

### Fraud: PaySim

PaySim is a **synthetic** dataset of mobile-money transactions. It was generated by a simulator calibrated on real logs from a mobile-money service in an African country (E. A. Lopez-Rojas, A. Elmir, S. Axelsson, *PaySim: A financial mobile money simulator for fraud detection*, EMSS 2016).

- Source: Kaggle, "Synthetic Financial Datasets For Fraud Detection" (`ealaxi/paysim1`)
- File: `PS_20174392719_1491204439457_log.csv`, placed in `data/raw/`
- Raw data is **not** committed to this repository (see `.gitignore`).

**Verified profile** (from `notebooks/01_fraud_eda.ipynb`):

| Property | Value |
|---|---|
| Rows × columns | 6,362,620 × 11 |
| Missing values / exact duplicates | 0 / 0 |
| Fraudulent transactions | 8,213 (0.1291%), i.e. 773.7 legitimate per fraud |
| Types containing fraud | TRANSFER (0.769% fraud rate) and CASH_OUT (0.184%) only |
| Simulated time span | steps 1–743 (one step = one hour) |

**Known data quirks** (kept and documented, not silently dropped):
- Balances are not a strict ledger. In 90.1% of legitimate TRANSFER/CASH_OUT rows the amount is larger than the origin balance, and the balance is floored at 0.
- Merchant balances are never recorded (always 0).
- 16 "fraud" CASH_OUTs have an amount of 0.
- Fraud amounts are capped at exactly 10,000,000.
- 320 of 743 steps contain only fraudulent transactions.
- `isFlaggedFraud` flags only 16 transactions and does not match the ">200,000 transfer" rule described on the dataset page.

## Installation

Python 3.11 is recommended. The code also runs on 3.9+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## How to Run (so far)

```bash
# 1. Place the PaySim CSV in data/raw/
# 2. Run the tests
pytest
# 3. Open the EDA notebook
jupyter notebook notebooks/01_fraud_eda.ipynb
```

If the CSV lives somewhere else, point to it with an environment variable:

```bash
export PAYSIM_PATH=/path/to/PS_20174392719_1491204439457_log.csv
```

## Limitations

- PaySim is synthetic. Patterns found in it may not carry over to real banking data, so findings should be read as a demonstration of method rather than real-world fraud intelligence.
